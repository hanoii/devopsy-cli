History, not rules: `internals/inherit.md` wins where they differ.

- The inherited keys come from the parent's current release, never the checkout, because a checkout (another branch, an old clone, CI) naming any key copied that value of the parent's into the child, whatever the parent's release said; `TestSyncInherit` pins it.
- An `inherit:` naming nothing empties the child's `inherit.env` since a review: following the hint to drop an only key left it inherited for good.
- The pending inherit file in a re-sync replaced writing `inherit.env` in place with a backup restored on abort, rejected because a holder killed outright would leave the new file over the old data. It exists because the child's labels follow an inherited variable: written after the copy, they lagged one sync. One file per sync because a second sync waiting for the lock has its file written already, and must never read or remove the first's.
- `parent.env` came on 2026-10-28, decided with the user, as a copy per child rather than a copy beside the child server's project `.env`: those levels are each server's, and two children on one server can have parents on two servers (an instance from each), each needing its own.
- The copy is written as the parent's files are, decided with the user after review 3: interpolated on the parent's side, `${DB_PASSWORD}` carried the parent's `shared/.env` secret out through a reference and `${COMPOSE_PROJECT_NAME}` the parent's name in; reviews 1 and 2 had made it the parent's values to keep `${HOST:?}` from failing, and it now fails only a child without a `HOST`, as on the parent's server. Review 4 made `copyText` keep every line of a file in order, a key defined twice reading as compose reads it, and keys as compose's parser takes them (`-`, `.`, `[]`, any script).
- Every key is copied, with no exclude list, decided with the user: what must not leave a server belongs in an environment's `shared/.env`.
- The header names the `--from` address as named, after a review where a laptop's server alias, stored in it, failed every refresh in CI. The copy is pending in a re-sync, moved on go, after a review where a sync that aborted left its `--from` as the source. The same-server copy of the parent's own `parent.env` came from a review of a chain whose middle shares the child's server; it goes under the child's own header, never the parent's, whose `--from` is not the child's, and alone for a `--from` with nothing to copy, so later copies follow it (review 2).
- One session for the inherited variables and the copy (`ParentVarsWriteScript`), and the copy's header read in the child's existing check of `current`, decided with the user on 2026-10-28: a release that does not sync adds the parent's trace and the write, the floor, since the values are on the parent's server, and carrying the copy in the upload would have made it the release's, which a rollback would bring back.

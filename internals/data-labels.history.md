History, not rules: `internals/data-labels.md` wins where they differ.

- The stop label replaced one boolean, `devopsy.sync.stop=true`, which answered three questions at once (down while its own data is copied? while any data is imported? for every copy?): `--import database` of a dump left the app serving during the load, and a child's app ran while its database was reloaded.
- Two labels for data, decided 2026-10-25: `devopsy.data=mnt|stream|none` said both whether a service has data and how it is copied, `stream` named devopsy's side of the plumbing, and a snapshot, which takes every service with data as files whatever its copy, would have read one label two ways; `custom` says whose job the copy is. Names rejected for the copy label: `pipe` (the mechanism again, and devopsy never pipes an export into an import), `scripts` (`copy=scripts` reads "copy the scripts"), `mnt` (the copy carries named volumes too), `rsync` (only the transport), `files` (reads as `./mnt/files`). The labels before these (`devopsy.sync.*`) are ignored like any label devopsy does not read, their old values (`mnt`, `stream`) unknown values, and a leftover `.devopsy/capabilities/sync/` is ignored: no migration code.
- An empty label value is an error rather than "no data" or "no copy", decided: a variable left unset by accident must fail, not stop copying; `copy=none` turns copying off and `false` says there is no data, so there is a word for each.
- `own,import` as a list was not added: the two overlap only on the service's own import, and a list waits for a use. A per-service stop window in a sync was rejected over one stop and one start of the union: one record, one restore, and Compose orders one `stop` by `depends_on`.
- Stopping the dependents of an imported service with no `import` value (implicitly) was rejected: an import of the app's own storage still needs a label, so every stop is visible in the compose file.
- The child's prepare names the dependents of any of its data services, not of what the parent copies, decided as an approximation: the child's list carries no `depends_on`, and the child does not know what the parent copies.
- `docker pause` was rejected because it flushes nothing (rsync sees what the kernel has, not a paused process's buffers) and Traefik 3.7 drops a paused container's router the next time it reads the containers, while a stopped routed container loses it at once (a 404 instead of a hang).
- The `restart: always` notice came from a reboot bringing a kept-down app back on half a database; the templates use `unless-stopped`.
- Entry names with whitespace were refused over a new list format (the child's list, the exclude label and the rsync modules split entries by spaces); names starting with a dash over `./` prefixes in every tool, after a review where a snapshot's take failed on find's predicate; `!` and `(` after a review following v0.52.1, where an export of an entry named `!` wrote none of its files, GNU find taking the name for its expression.
- A service with data's named volumes became data too on 2026-10-25: a named volume is a host directory as well, and a copy or a snapshot that skipped a database kept in one would have looked complete. `ensureVolumes` was checked on compose v5.5.0 (no "not created by Docker Compose" warning when the two labels are set; compose's own config hash is left out).
- Rejected for these labels: a `push` script with helpers (it only works from the parent's server to the child's, never for a file, a laptop or a relay, while `export` and `import` give the same freedom and serve `--export` and `--import` too); export and import commands in compose labels (scripts do not belong in labels); `stop` as a value and a sub-label at once, or a hold sub-label for streams only (two orthogonal labels instead); a dump into an entry of `mnt` as devopsy's way (at rest on the parent, twice the disk, cleanup and completeness the project's again; fine for a project that wants dumps on disk anyway); an `--export` that never stops a service (the scripts are written for the label, and a `run --rm` export against a live service fails or copies inconsistent files); stopping other services from inside the import script (devopsy would not record, restore or keep down what it stopped); `files` as the method's name; an empty `devopsy.data` to turn copying off; splitting the capability into `sync` (prepare, finish) and `data` (export, import), since it is one concept named like its labels, and snapshots want `prepare` and `finish` too.

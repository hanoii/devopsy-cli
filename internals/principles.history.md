History, not rules: the root's Principles section wins where they differ.

- `devopsy-compose.yaml` was decided on 2026-10-23 as the one file devopsy adds beside a release: a hold by digest is the one fact compose can only take as a service's `image:`, which no variable or label can express; the accepted cost is that a plain `docker compose` on a server lacks the file.
- "Nothing is frozen before 1.0.0" and the two limits on reviews (no tests of specific older versions, no code for an older operator's or server's scripts, no version-skew edge cases) were decided on 2026-10-26, after review rounds were spent on mixed-version edge cases; mixed versions are not a concern beyond the gate itself, since a new behavior an older server lacks is a named feature or a protocol bump that refuses before anything changes.
- devopsy replaces itself with the command it runs so that `devopsy up` behaves as `docker compose up` does; the accepted cost is that nothing runs after the command (no cleanup, no notice), hence the detached `--upgrade-check` and the server scripts for what must happen after.
- Push over pull was chosen for having no control plane, daemon, webhook or deploy key: one command from anywhere; the accepted costs are that a release needs the operator until its switch and that syncs across servers work only through the operator's forwarded agent.
- Names from project, instance and environment alone replaced a `path:` key, compose's `name:` (overridden through `COMPOSE_PROJECT_NAME` in `devopsy-target.env`), the checkout's folder and the local `COMPOSE_PROJECT_NAME`; the `-` join can collide (`a-b` + `c`, `a` + `b-c`), which `--check-names` refuses (internals/releases.md).
- A server-wide variable layer existed as `/etc/devopsy/devopsy.env` and went, and a file the proxy's release would write for other projects was rejected: nothing hidden on a host may change what a project sees, so what a server knows is its targets' variables or an export of the project that owns it; the cost is that CI and laptops name the server (`DEVOPSY_SERVER`, the address).
- "What is deployed decides on the server" costs that every server's devopsy must keep up (`devopsy @<server> --upgrade`).
- "Before the switch anything cancels; after it nothing interrupts" costs that a stuck run step can only be stopped on the server.
- "Check everything before changing anything" costs the marker files and the code that reads them; the alternative, a server needing someone to log in and guess after a cut-off session, was never acceptable.
- "The server never waits on the operator for long" costs that an operator frozen past the quiet time (a laptop asleep, Ctrl-Z) cancels, cleanly.
- "Words are never built-ins" costs that devopsy's features read as flags (`--release`, `--sync`), never as subcommands; `--` is the escape hatch.
- "Projects own policy; devopsy owns mechanics" costs that the templates carry the conventions and devopsy only reports facts to them (the `finish` word, exports).

History, not rules: `internals/other.md` wins where they differ.

- `--status` reads the last completed sync from the child's own `SyncedFile` since 2026-10-27: read from the session logs' `SyncCopied` lines before, it missed every sync whose session was lost before the operator saved its log.
- `images.StatusLines` names a container running another image than the current release's file gives it since review round 8 of the images work, when `--status` was silent about a rollback whose newer containers ran on.
- `--status` gathers facts where the environment is and formats them on the operator since 2026-11-07, as `--server-info` did: before, the server's devopsy printed the containers and the capability's lines as text the operator passed on, so it could not color, judge or turn them into JSON, and the layout followed the server's version; it exits 3 when a warning shows, as `--server-info`, for CI and agents after a release.
- The status capability's tab-separated lines with a level (2026-11-07) replaced free text padded by hand, which the templates padded one column off devopsy's and devopsy could not tell from a problem; JSON or YAML from `sh` was rejected (escaping by hand, no `jq` on a server, YAML misreading `on` and `no`), and so were escapes inside a value: a line per fact needs neither. A level field won over "a fix means a warning", so a hint can carry a command without warning.
- A container exited with 137 or 143 is no warning: `docker compose stop` ends a process with SIGTERM or SIGKILL, so a service stopped by hand would read as failed.
- Review round 1 of `--status` (2026-11-07): a paused container warned in `--server-info` but not in `--status`, so both judge through `containerTrouble`, which also gave `--server-info` the exit on an error; a one-off was listed as a second container of its service; the header's commands sat inside its lines, so `--json` gave none for the states that need one most; JSON commands were not quoted as the text's.
- Review round 2 (2026-11-07): the header's fixes named the target as typed, which a user-level alias without `source:` refuses for a release or a rollback, so they name `HintAddress`'s, as the scripts' hints did; a fix had three shapes (pairs, `report.Remedy`, a status type of its own), now `report.Remedy` with JSON tags from the pairs; `--server-info`'s docs still listed the container troubles before `containerTrouble`.
- The disks joined `--status` on 2026-11-07, judged by `--server-info`'s thresholds through one helper, without its reflink try: `--status` writes nothing.
- Behind the door, `--status` listed no services without a container until 2026-11-07: the door's `config` makes the binds' entries, so it was skipped there, until `composeServices` ran the real docker as the project user, as the door's own render does, since `config` needs no daemon.
- `--server-info` printed its facts as rows padded to 12 and said its warnings after them through `report` on stderr until 2026-11-07, when it took `--status`'s entries and formatter: a warning sits under the line it is about, and `--json` gives the facts with each warning and its fixes. A warning of its own entry, rather than added to its line's, keeps the JSON's warnings one per problem, so `--status`'s disks went the same way.
- `--status` with a server scope was rejected: `@vm1 --status` would mean two things by whether `vm1` is an environment.
- `--server-info` refuses on macOS since 2026-10-30: nothing marks a machine a server, and there the facts were half missing or Docker's VM's (no swap, Docker's data on the Mac's `/`, its logs unbounded by a `daemon.json` OrbStack never reads).
- The kernel memory warning (2026-10-30) came from a 2 GB server whose kernel's own allocations ran out with memory free (an initramfs out of memory, a deadlocked kernel): Kexec HandOver's scratch, which the 7.0 kernel of Ubuntu 26.04 turns on, is CMA pageblocks no CMA area counts, checked in the kernel's source (`init_cma_reserved_pageblock` adds to the zone's count, `totalcma_pages` only counts areas); `/proc/pagetypeinfo` would say it too, but it is root's.
- The clock check (2026-10-30) came from a server whose network blocks NTP; the server's time is taken last and compared at the facts' first byte so it is off by the way's one-way time at most.
- Containers are read from one `docker inspect` of all, read even when it fails, after a review found a container gone since `docker ps` failing the whole report.
- An environment's state was judged twice until 2026-11-07, by `--status`'s header and by `--server-info`'s list of problems, which had drifted: `--server-info` only said an import or a restore under way, which `--status` warned, since what it stopped stays down, and worded the rest its own way. `envState.entries` judges it for both since, `--status`'s judgment kept.
- The AppArmor warning was settled in review round 2 from moby's source: `docker info` lists AppArmor whenever the kernel has it, and Docker loads its profile with `apparmor_parser`, without which no container starts.
- The agent skill was decided on 2026-10-27: installed into `.agents/skills/devopsy`, which Codex, Cursor and the skills installer share, with a link from `.claude/skills/devopsy` because Claude Code (2.1.x) read only its own directory (anthropics/claude-code#31005); the link is relative from where the link really is because a `~/.claude` in a dotfiles checkout would dangle otherwise.
- `Install` keeps an edited copy since 2026-11-01: it replaced any file marked as devopsy's before, so running it after an upgrade overwrote what a user had added to the copy.
- Sessions refuse passwords since 2026-10-29: a devopsy server takes keys only, so a prompt meant a missing key, asked again per session of a release, or with a child's set stopped while a sync's push waited for it; `BatchMode` was rejected because it would refuse a passphrase and a new host key too.
- `--context-hash` folds base images in since 2026-10-23, with no opt out: a hash that ignored bases reused `ctx-<hash>` images forever, so patched bases never arrived; the cost is a registry request per base and a hash that needs the network.

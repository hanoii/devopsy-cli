History, not rules: `internals/config.md` wins where they differ.

- `~/.devopsy` was rejected as the user's config directory: project discovery walks up looking for `.devopsy/`, and a home directory holding one would have been taken for a project.
- A `path:` key once named a target's directory on the server; it went when names were made to come only from project, instance and environment (the root's Principles), so that the same target lands in the same place from any laptop or CI.
- `server:` in a project's config is an unknown key for the same reason: one checkout releases to any server, so the server is the target's (the address, `DEVOPSY_SERVER`, an alias), never the project's.
- Instances became all or nothing (`instances: true`) so that a project's environments never mix `<project>/<env>` and `<project>/<instance>/<env>` on one server and `--environments` lists one layout.
- A parent's server is never guessed from the child's: a guess would copy the wrong data.
- An unresolvable parent is recorded (`ParentErr`) rather than failing the load, so that every command but a sync works on a child whose parent's server is unknown locally.
- `confirmUnnamedSecrets` runs locally and without a session, by design: a secret-like name only in the server's files is left to `--vars set`, which asks the same question.
- `parent:` left `defaults:` on 2026-11-01: `defaults: {parent: prod}` made every environment but prod a child, a new or misspelled one included, copying prod's data with nothing in its own definition saying so.
- An environment in `config.local.yaml` replaced the project's of the same name whole until 2026-11-01, while its `defaults:` merged: a local file changing one key had to repeat the rest, and could not clear a parent without redefining the environment. It merges since, as `defaults:` do, a breaking change (`feat!`).
- A server took no `:` until 2026-11-06, the address splitting at its first one, so a port went only in `~/.ssh/config` or in `DEVOPSY_SSH_COMMAND`, and an IPv6 address only behind a Host. A `-p` in `DEVOPSY_SSH_COMMAND` reaches every server a command does, a parent on another server included, so the address splits at its last `:` since, the server holding a port or an IPv6 address. Rejected on the way: quotes around a server (the shell eats them, and `--from` would need them too), another separator (every address in the docs, templates and habits changes, and an IPv6 address with a port still needs brackets), `--ssh-host`/`--ssh-port` flags or a port variable (a hint copied without them silently goes to port 22), and `ssh://` destinations handed to ssh (`-p` is what a sync across servers already passes).
- The port check (`PortError`) first ran at three call sites (the command's target, a sync's parent, `--environments`), so `--inherit` and the `parent.env` refresh reached a parent whose port `DEVOPSY_SSH_COMMAND` overrode without a word (review, 2026-11-06). It runs as a target loads strictly since, which every target, parent and `--from` goes through. In `SSHStreams` it would have been one place too, but after a sync's first session, and its errors printed without their fixes. The same review had `ParseServer` refuse a leading `-` (`-oProxyCommand=...` from a project's `.env` reached ssh as an option) and shell characters, and write `022` as `22`, which `ssh -G` prints.
- A session's addresses are checked as addresses (2026-11-11) because the door's caller sets them, as any process in a session can: a value that is no address, or past its cap, is dropped and the hint said in words, so a forged one reaches only its sender's own messages.

- A server's `gc:` (2026-11-12) holds the ages `--gc` goes by, beside `releases:` and `snapshots:`, since they are the server's to choose. Days are taken as `<n>d` because Go's durations stop at hours, and an age of zero or less is refused: it would remove a one-off container the moment it exits.

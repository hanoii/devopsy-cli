History, not rules: the root's Conventions section wins where they differ.

- The one line format (`devopsy: ` on every line, the level's tag, `| ` for details and fixes, `$ ` for a command to copy) was chosen so that each line says by itself that it is devopsy's among compose's, Docker's and the steps' output, and coloring, logs and grep never need the line before. Rejected: `slog` (key=value attributes, not a message with details and fixes), indented continuation lines (ambiguous with compose's), and times on lines (the logs have them; a total, when one is wanted, comes from the local devopsy's own clock, in the message).
- `--say` (Protocol 5) replaced scripts' own `echo` lines so that every message has the format; `basePrelude`'s checks of the server's devopsy and the `--ssh-keys` scripts keep a plain `echo` of a line built by `report` (`echoLine`) because they cannot rely on the server's devopsy.
- `TestNothingSaysAround` came after messages printed around `report` missed the format and the level.
- Hints name the address as typed because the command must work when copied, and an alias with `source:` releases only from its checkout.
- On 2026-11-01 `releaseRef` (locally) and `hintAddress` (in scripts), which both named the alias only with `source:` but with slightly different fallbacks, became one function, `remote.HintAddress`; `targetRef` stayed for hints of commands that need no checkout.
- Secrets became opt in (`secrets:` in `config.yaml`) after a regex guessing from names masked the wrong things and missed others; "everything in `.env`" and a mask-everything fallback were rejected with it.
- `--yes` never lets a secret-like name through (`public:` does) because `--yes` skips prompts, which CI passes everywhere.
- Colors go by what a line starts with, never its words (`report.Paint`): devopsy's errors red, warnings yellow, info cyan, debug, trace and the `| ` bar dim, a `$ ` command bold; Compose's done steps green, steps on the way dim, another tool's errors red (superseded below); help is colored by layout (headings end with `:`, entries start with two to seven spaces, `@t` magenta, `@s` yellow). Lines colored already are left as they are, and `report.Colorize` is line-buffered and used for terminal writers only.
- Color is decided by `styleFor` (a terminal without `NO_COLOR`) or forced by `cli.ColorForced` (`FORCE_COLOR` not `0` or `false`, or the internal `cli.ColorEnv`); devopsy never exports `FORCE_COLOR` because in a session it would reach every tool, which would then color what scripts capture.
- On 2026-11-01 another tool's lines stopped being red by their words (`foreignError` matched error, fatal or panic anywhere in a line): an app's log line or a test's name turned red, against the rule that a line's color comes from how it starts. The same day `ColorEnv`, defined in both `cli` and `remote`, was left to `remote` alone, since `cli` imports it.
- The pseudo-terminal on the server for activations (internals/sessions.md) replaced `-t` sessions so that BuildKit draws its live progress through the pipe while the session stays one path for a terminal and CI.
- The command scope lines (`## Run:`, `## Needs:`) are checked in `runRemote` before connecting because an older server's devopsy would have run a local-only command there.
- `DEVOPSY_INTERNAL_*` names are never documented as settings so that any release may change them; on 2026-11-01 the code had, among others, `COLOR`, `TTY`, `ENV_COMPUTE`, `WATCH`, `SYNC_WATCH`, `SYNC_ID`, `HEARTBEAT`, `HEARTBEAT_EVERY`, `COMMAND_TARGET`, `IMPORT_END`, `INHERIT_FILE`, `SYNC_NEEDS`, `HOOK_START`, `SNAPSHOTS`, `BASE`, `SNAPSHOT_KEEP`, `SNAPSHOT_RELEASE_KEEP`, `SNAPSHOT_MIRROR`, `RESTORE_SNAPSHOT`, `HELD_STOPS`, `RESTORE_ENV`, `RESTORE_BY`, `TARGET_FILE`, `DOTENV_FILE`, `NO_RELEASE_COMPOSE`, `IMAGES_ACCEPT`, `IMAGES_MODE`, `IMAGES_LOCK`, `IMAGES_LEFT`, `SYNC_RESET`, `SYNC_IMAGES`, `SYNC_IMAGES_SUM`.
